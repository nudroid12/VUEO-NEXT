# VUEO consolidated WebView session v5 — TV/mobile

Apply these root-relative cumulative files over app repo 54 plus the earlier WebView patches, build with the existing workflow, and install. Then apply/refresh Cloudbank VidLink v1.1.0. This replaces v1-v4 changed source files; no YML, native VidLink domain, provider identifier or movie ID is included. shared/core/build.gradle.kts adds AndroidX WebKit 1.14.0; its remaining contents come from the supplied repo 54. Check any independent dependency changes before overwriting that file.

The previous media policy accepted only MP4/HLS paths in native interception while the legacy MIME-based JS capture could see DASH. The separate provider API call also forced an HLS playback environment while the real site can select a different environment. The latest phone log proves browser video data and nativeObserved=0, but does not itself identify the captured transport. This update covers both gaps without asserting that DASH was conclusively the phone's transport.

Generic opt-in: captureSessionResponses=true with jsonResponsePrefixes. Only requested HTTP origin/path prefixes ending in '/' can supply successful JSON objects. Native validation repeats the prefix/scheme/port/userinfo checks. Up to four distinct response records are retained; each JSON text is limited to 262144 characters and each bridge message to 524288. Objects are returned internally to the provider; bodies, signed URLs and cookies are not added to debug logs. Existing runtime summary logs only counts/timing. New JSON and response capture remain disabled by default.

The existing fetch/XHR response hooks reuse their existing response inspection: successful bounded API JSON is captured without another HTTP call. Successful HTTP 200/206 media responses get responseObserved=true, distinct from networkObserved=true from native request interception. The latter retains authoritative request headers; response-only capture uses configured WebView UA, document Referer/Origin and refreshed CookieManager cookies, not a claim of observed wire headers. Final native HTTP probing remains necessary.

Native MPD paths now qualify with the same host/path exclusions. Session completion requires captured JSON plus an observed request/response on an approved media host/path; the existing 250ms settling delay is used. No extra timer, longer timeout, preflight, retry or subtitle request is added. Raw extensionless or unapproved-host successful media can be retained via MIME capture but cannot trigger early completion. Provider validation still must correlate every returned URL with the verified captured API route. Session response capability is sessionResponseVersion=1; native request, response and browser readiness remain separate facts.

For this new opt-in only, AndroidX WebKit document-start script installation is attempted before loadUrl, limited to the original page origin and gated by DOCUMENT_START_SCRIPT support. The existing callback injection remains as fallback. Document-start support is reported as documentStartHook, and cleanup removes the script. The script guards against duplicate installation. Existing providers do not opt into this new startup behavior.
